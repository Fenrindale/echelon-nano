# 추론 실패와 문맥 복구

업무 도구가 정상 완료된 뒤 다음 모델 추론만 실패할 수 있다. 기존에는 원인이 없는 `response.failed`를 `inference_failed`로 기록하고 같은 요청을 세 번 더 보낸 다음 전체 실행을 종료했다. 오류 본문의 상세 원인은 저장되지 않아 과거 실패의 제공자 내부 원인은 소급 확정할 수 없다. 짧은 추론이나 수정한 지시문의 성공도 기존 업무 요청의 성공을 증명하지 않는다.

## 구현

- HTTP/SSE 오류의 고정된 분류, HTTP 상태, 종료 이벤트 종류, 오류 코드·유형·메시지의 SHA-256과 메시지 바이트 수를 보존한다. 제공자 원문, 계정 식별자, 입력, 자격증명과 비공개 추론은 오류 이벤트에 저장하지 않는다. 제공자가 실패 시 사용량을 반환하면 별도 기록하고 누적한다. 반환하지 않으면 미확인으로 남긴다.
- 명시적인 잘못된 암호화 문맥, 문맥 초과와 출력 중단은 문맥을 복구한다. 설명 없는 추론 실패는 최초 요청과 최대 세 번의 재시도 후 동일 요청을 반복하는 대신 문맥을 복구한다. 네트워크·일시 서버 오류는 기존 지수 지연과 일시정지·취소 제어를 유지한다.
- 원본 대화와 보호된 도구 출력은 보존한다. 새 문맥은 서버의 원래 목표, 역할, 현재 Work Order, 고정 근거, 작업 상태, 확인된 실행 영수증 및 운영 요약으로 시작한다. 이전의 암호화 항목과 도구 호출 묶음을 그대로 보내지 않는다. 요약이 실패해도 구조화된 영수증으로 복구한다.
- 확인되지 않은 모델 출력은 실행하지 않는다. 미처리 도구 호출이나 읽기 묶음이 있으면 이 복구를 수행할 수 없다. 실제 도구의 불명확한 결과는 기존 재조정 경로를 따르며 자동 재실행하지 않는다.
- 연속 실패의 문맥 복구는 세 번까지다. 성공한 추론 후 복구 횟수를 초기화한다. 영구 오류를 무한히 숨기지 않으며 인증·할당량·정책 거절은 구분해서 종료한다. 수동 실행의 호출 한도를 늘리지 않는다. 토큰 사용량은 관측하며 새 토큰 상한을 추가하지 않는다.
- 실패한 추론의 명시적 재개는 원래 실행 ID와 기록을 유지하면서 문맥 복구를 예약한다. 서버 재시작 자체로 업무를 자동 재개하지 않는다.

## 검증

`docker build --target checks .`는 오류 형태별 분류, 안전한 진단, 사용량, 재시도/복구 전환과 실패한 응답의 도구 실행 차단을 검사한다. PostgreSQL 검사는 기존 불변 기록과 트랜잭션을 별도로 확인한다.

연결된 OAuth 계정을 사용한 `scripts/Verify-InferenceRecovery.ps1`은 **18432 격리 복사본**에서만 실행한다. 실제 파일 하나를 생성한 뒤 해당 합성 Task를 일시정지하고, `InvalidContext`에서는 손상된 암호화 항목을 넣어 실제 제공자 거절과 복구를 확인한다. `-Scenario ExplicitResume`에서는 모델 재시도를 소진한 기존 형식의 실패 상태를 만들어 명시적 재개를 확인한다. 두 경우 모두 이전 영수증의 불변성과 최종 파일 두 개의 정확한 내용, 파일 생성 중복 부재, 같은 Work Order와 원래 목표를 검사한다. 이 인위적 변경은 실사용 Task에 적용하지 않는다.

`Verify-Persistence.ps1`, `Verify-Recovery.ps1`과 `Verify-LLMLoop.ps1`은 네트워크 중단, 제어, 재시작 및 역할별 실제 실행을 별도로 검증한다. 단위 테스트, 격리 실계정 검증과 실사용 Task의 실제 진행은 서로 다른 증거다.
