# 중앙 지식과 Task 지역 지식

중앙 지식은 이후 업무의 의사결정이나 행동을 바꾸는 재사용 자료다. 사실이고 출처가 있다는 이유만으로 중앙에 채택하지 않는다. Data/Info/Intel은 내용의 성격이고 보관 범위와 독립적이다.

| 기록 | 기본 보관 범위 |
| --- | --- |
| A 작업에서 특정 오류가 발생했다는 진행·상황 보고 | 원본 Task |
| A 작업의 처리 건수, 당시 차단 상태, 임시 원인 후보 | 원본 Task |
| 특정 오류 조건에서 피할 행동과 재시도·검증 기준 | 출처가 실제 기준을 뒷받침하면 중앙 후보 |
| 반복해서 쓰는 구성·업무 규칙·사용자 선호 | 적용 조건과 유효성을 명시한 중앙 후보 |
| 후속 작업에서 참고할 공식 문서의 정확한 URL·절 위치 | 중앙 Data 후보, 본문 복제 불필요 |

일회성 사건에 “다음에도 확인하자” 같은 일반적 문장을 덧붙이는 것은 재사용성의 근거가 아니다. 원문이 지지하지 않는 보편적 교훈도 만들지 않는다. 중앙 채택 0건은 정상적인 분석 결과이며, 업무 완료나 원문 분석 완료의 실패 조건이 아니다. 범주별 채택 할당량은 없다.

## 채택과 조회

Handler는 지식 문서에 `retention_scope: "central" | "task"`와 중앙 후보의 `reuse: {applicable_when, decision_or_action, evidence}`를 제시한다. 기본은 Task 지역이다. `evidence`는 제출 본문의 실제 연속 인용 또는 정확한 출처 URL이다. 서버는 범위, 길이, 인용 일치를 검증하고, Analyst가 의미상 재사용성과 출처의 한계를 판단한다. 형식 검증만으로 의미상 품질이 보장되지는 않는다.

Analyst의 `knowledge.publish` 결정은 `accept`, `local`, `reject`다. `accept`는 근거가 있는 재사용 기준을 요구한다. `local`은 내용·분류·태그·출처·진위·실패 상태를 보존하고 원본 Task에 보관한다. `reject`도 제출 원문과 반려 이유를 보존한다. Analyst는 내용을 새로 작성하거나 외부 자료를 수집하지 않는다.

`knowledge.read {op:"list"}`는 중앙만 반환한다. 지역 지식은 `{op:"list", retention_scope:"task", source_task_id:UUID}`로 원본 Task를 명시해 조회한다. 기존 Handler 권한은 그대로다. 자기 제출 상태와 전달받은 Context Pack 참조를 사용하며 중앙 DB 직접 읽기 권한을 얻지 않는다.

새 Context Pack의 검색·명시적 선택·프로토콜 로딩·관계 확장에서는 현재 중앙에 채택된 항목만 사용할 수 있다. 이전에 전달된 Pack의 버전·본문 해시·참조는 바뀌지 않는다. 이후 지역으로 이동한 기록도 이미 전달된 참조로 당시 근거를 재현할 수 있으며 현재 범위 변경을 알린다. 지역으로 옮겨진 실패 기록도 삭제하지 않는다.

## 기존 항목 재심사

0015 마이그레이션은 기존 항목을 `review_needed`로 표시한다. 중앙 검색으로 무조건 재유통하지 않으며, 개정과 채택 이력은 수정하지 않는다. 외부 모델 전송 금지 항목은 자동 심사에서 제외해 재심사 대기 상태로 남긴다.

운영자 API `POST /v1/operator/knowledge-reviews`는 `{tenant_id, task_id, request_id, connection_id, model}`을 받아 현재 항목의 불변 스냅샷으로 심사를 시작한다. 연결된 모델과 Task의 전송 정책을 확인한다. 실제 Analyst 추론은 항목별 중앙/지역 분류와 근거 메타데이터만 반환하고, `knowledge.classify`를 통해 새 개정을 만든다. 기존 업무 본문·출처·실패 이력은 변경하지 않는다. 상황 기록에서 새로운 일반 지식을 작성하는 작업은 이 경로의 권한이 아니다.

`GET /v1/operator/knowledge-reviews/{id}?tenant_id=...&task_id=...`는 총량·진행·중앙·지역·충돌 건수와 모델 사용량을 반환한다. `/control`에 동일 범위와 `action:"pause"|"resume"`을 보낸다. 재시작 후에는 명시적으로 재개한다. 모델 응답과 분류 효과 키를 저장하므로 이미 확정한 판단이나 개정을 재실행하지 않는다. 동시 변경은 `stale`로 보존하며 심사 완료로 부풀리지 않는다. 토큰 상한 없이 역할·단계·모델·도구별 사용량을 수집한다.

Task Knowledge 화면에서 지역 보관과 중앙 채택을 구별하고 제출 본문·판단 이유·개정 이력을 볼 수 있다. 본문 분석의 최초 채택 건수는 역사적 영수증이며, 현재 중앙/지역 건수와 따로 표시한다.

## 검증

`scripts/Verify-Retention.ps1`은 격리된 18432 환경에서 실제 OAuth Analyst가 일회성 상황 2건을 지역으로, 재사용 규칙과 문서 참조 2건을 중앙으로 구분하는지 확인한다. PostgreSQL 검증은 재사용 근거 없는 중앙 채택 거부, 지역 보존, 새 Pack에서 제외, 기존 Pack 참조 재현, 멱등 개정과 역할 제한을 확인한다. `Verify-BodyIngestion.ps1`은 실제 대화의 재사용 규칙과 지역 상황을 함께 검증하며 범주별 채택량을 강요하지 않는다.

`Verify-BodyIngestion.ps1 -LocalOnly`는 중앙 채택 0건에서도 지역 기록을 보존하고 정상 완료하는지 검사한다. `Verify-RetentionLoop.ps1`은 일반 업무의 실제 Handler·Agent·Analyst 실행과 별도 선별·채택 단계를 검증한다. 두 본문 시범과 일반 업무 시범은 모두 격리 환경에서만 실행한다.
