# 첫 로컬 베타 구현과 검증

베타 0.2 · 2026년 10월 19일 · Windows / PowerShell 7 / Docker Desktop Linux.

`PLAN.ko.md`의 첫 사용 가능한 베타와 세 가지 실무 시범을 기준으로 한다. 아래 검증은 소유한 합성 자료를 사용했으며 실제 회사 시스템의 배포·발송·업무 변경을 뜻하지 않는다. 계정 원문, 자격증명, 체크포인트와 복원 자료는 공개하지 않는다.

첫 버전의 운영자 로그인은 사용자의 요청에 따라 유보했다. 로컬 화면에 접속한 사용자는 운영자이며 자동 세션은 CSRF 처리용이다. ChatGPT 모델 OAuth 및 역할별 서명·Task·Work Order 권한은 계속 검사한다. 원격 다중 사용자 배포의 인증 체계로 사용하지 않는다.

## 재현 가능한 검사

### 실행 지속성과 Handler 감독 · 2026-10-21

추론의 고정 120초 종료를 연결 30초·무수신 300초·단일 요청 900초로 분리했다. 완료 응답을 받지 못한 일시적 모델 생성만 2–60초 간격으로 재시도하고, 시도별 호출·불명확한 사용량·대기 시각을 보존한다. 인증·확인된 과금 한도·정책·DB 오류와 불명확한 업무 도구 효과는 자동 반복하지 않는다. 중지·취소와 서버 재시작 후 명시적 재개를 유지한다.

자동 Task는 호출 수·시간·컨텍스트 경계에서 모델 라운드를 새로 시작하며 목표·역할·기존 Work Order·확정 영수증을 보존한다. Handler는 원래 목표의 완료 근거와 남은 업무를 평가하고 가능한 다음 행동이 있으면 재계획한다. 파일 없는 부분 결과도 회수할 수 있지만 완료 파일 결과에는 실제 소유 산출물을 계속 요구한다. 이전 Work Order의 서버 수집 결과·관찰·영수증을 전달하고 Handler가 이 실행의 이전 결과를 다시 조회할 수 있게 했다. Agent는 자신의 배정 업무만 완료 판단하며 다른 Work Order에 접근하지 않는다. 큰 이전 이력은 ID·해시와 필요 시 재조회로 처리한다.

Rust 38개·OIDC 1개·웹 11개와 격리 PostgreSQL 7개가 통과했다. 실제 OAuth 장애 주입 검증은 공급자 네트워크 단절·재시도 중 일시정지·라운드 전환·부분 결과→재계획→이전 결과 재조회→완료의 13개 검사를 통과했다. 두 Work Order와 한 파일만 생성했고 실제 바이트와 불변 해시를 확인했다. 27회 호출과 확인된 81,181토큰을 기록했으며 미완료 요청의 사용량은 추정하지 않는다. 이것은 장애·재계획 기능 검증이며 성능 절감 표본이 아니다.

강제 중단·명시적 재개는 새 목표 전용 실행으로 20개 검사·16회·42,424토큰을 통과했다. Worker 실행·Work Order·출력 파일은 각각 하나이며 원래 실행의 replayed 영수증과 실제 스크립트·해시·출력 경로를 Handler 조회로 확인했다. SSE 범위와 커서 재생도 확인했다. shell/HTTP 영수증은 제한된 미리보기와 페이지 조회로 전달하고, 과거 기록에 없는 메타데이터를 채워 넣지 않는다.

기존 OAuth 역할 루프는 52개 검사·13회·28,179토큰, 본문 지식화는 8회·15,805토큰으로 Data/Info/Intel 3건과 참조 관계 3개·거짓/실패 이력·봉인·일시정지/재개를 확인했다. 역할 행렬 100개·양성 dispatch 5개·금지 dispatch 72개·운영자 거부 8개, 지식 API 35개와 Beta 28개도 통과했다. 이 격리 검증은 액세스 토큰만 사용하며 토큰 갱신을 새로 검증한 것으로 집계하지 않는다. 전체 업무 시나리오 74개는 기존 완료 기록 재검사다. 실제 사용자 원문·계정·원본 증거는 공개 저장소에 포함하지 않는다.


### 대화 본문 지식화 · 2026-10-20

대량 대화 백업을 기존 Task 안에서 이어 처리하는 전용 작업을 추가했다. 목록 참조와 실제 본문 지식을 구분하며 Agent의 원문 인용 → Handler 문서 작성·제출 → Analyst의 실제 제출 ID 심사·채택을 사용한다. Data/Info/Intel의 하위 채택 ID·버전을 고정해 관계를 만들고, 반려·의존 차단·원문·완료 구간·모델 결정을 보존한다. 일반 실행의 짧은 호출 수와 후처리 후보 수 제한을 본문 전체 처리에 적용하지 않으며 토큰 사용량은 기존 역할·단계·모델·도구 집계에 포함한다. [본문 작업 API와 검증](CONVERSATION_INGESTION.md)을 따른다.

Rust 34개·OIDC 1개·웹 11개와 격리 PostgreSQL 7개가 통과했다. 소유한 합성 대화를 실제 OAuth 모델로 분석해 Data/Info/Intel 3건 채택, 고정 참조 관계 3개, 거짓·실패 이력, 원문 재전송·봉인 및 일시정지·재개를 확인했다. 최초 검증의 근거 부족 반려도 보존하고, Analyst에게 같은 구간의 다른 확인된 인용을 함께 전달하도록 수정했다. 역할 행렬 100개·양성 dispatch 5개·금지 dispatch 72개·운영자 거부 8개, 지식 35개와 Beta 28개도 통과했다.

기존 역할 루프는 실제 추론 13회·27,011토큰과 52개 검사로 재확인했다. 이 격리 실행은 액세스 토큰만 사용했고 실행 중 갱신은 새로 검증하지 않았다. 전체 업무 시나리오 74개는 기존 완료 기록 재검사이며 신규 업무 실행이나 성능 표본으로 집계하지 않는다. 실제 사용자 백업·지식 내용·계정·원문 증거는 공개 저장소에 포함하지 않는다.

### 토큰 상한 유보와 사용량 수집 · 2026-10-20

누적 토큰 수에 의한 중단과 설정 범위 검사를 제거했다. 이전 요청의 `max_total_tokens`는 요청 재전송 호환을 위해 받지만 실행 제한에 사용하지 않는다. Handler는 토큰 예산을 선택하지 않으며 새 설정에는 0을 기록한다. 호출 수·시간·입력 크기 제한과 중지·취소는 유지한다. 자동 업무 호출 예산은 역할 조정에 필요한 32–48회로 정하며 기밀 지침은 관련 업무에만 제공한다.

완료 응답의 입력·출력·캐시·총 토큰을 불변 이벤트에 보존하고 운영자 metrics API에서 역할·단계·모델·도구 결정별로 집계한다. 도구별 수치는 도구 선택 추론의 사용량이며 도구 자체의 실행 비용이 아니다. 미완료 응답은 사용량을 추정하지 않는다. 이 데이터로 이후 상한을 정하며 계정의 잔여 한도·비용을 대신 계산하지 않는다.

Rust 31개·OIDC 1개·웹 11개가 통과했다. 실제 OAuth 역할 루프의 53개 검사는 기존 토큰값 1,000으로 시작해 14회·33,581토큰으로 업무 완료, 네 집계 차원의 원본 합계 일치, 다른 tenant의 조회 차단과 호출 예산 중단을 확인했다. 격리 실행은 액세스 토큰만 사용했으며 실행 중 갱신은 새로 검증하지 않았다. 역할 행렬 100개·양성 dispatch 5개·금지 dispatch 72개·운영자 거부 8개와 Beta 28개도 재확인했다. 기존 업무 시나리오 74개는 완료 기록의 재검사다.

목표·첨부 자동 실행은 28개 검사·22회·64,731토큰으로 보고서·첨부 권한·바이트·불변 해시와 Handler의 토큰 상한 없는 설정을 확인했다. 목표만 입력한 강제 중단·명시적 재개는 17개 검사·16회·36,742토큰으로 통과했다. Worker 실행·Work Order·출력 파일은 각각 하나이며 원래 영수증을 회수했다. 변경 전 10,000토큰 설정 때문에 중단된 합성 검증 기록도 실패 이력으로 보존한다. 실제 사용자 Task는 대신 재실행하지 않았다.

### Task 연결 자동 설정과 서버 증거 · 2026-10-20

이 절은 아래 최초 기밀 구현의 ‘운영자 등록 커넥터 필요’ 제한을 대체한다. Handler가 목표 또는 선택한 설정 파일의 서비스 주소로 `credential_bindings`를 직접 정하고 Agent가 고정 신원 API를 사용한다. 연결 프리셋은 선택 사항이며 등록·승인 절차가 아니다. 다음 Task의 기존 묶음 선택도 Handler가 수행한다. Work Order 조회에는 실제 Vault 왕복의 감사 영수증과 서비스 신원 관찰을 포함해 Handler가 Agent의 설명과 교차 확인한다. 미구현 어댑터를 권한 부족으로 설명하지 않도록 안내도 수정했다.

Rust 30개·OIDC 1개·웹 11개 및 격리 PostgreSQL 6개 검사가 통과했다. `Verify-TaskBindings.ps1 -Live` 25개는 프리셋 0개 상태의 설정 파일 주소 선택·실제 신원 요청·재사용·범위 변경 거부·Handler의 서버 기록 조회를 확인했다. 실제 OAuth LLM에는 목표와 합성 첨부만 제공했으며 20회·58,628토큰으로 Handler 설정 → Agent 적재·인증 확인·보고서 → Handler의 관찰 ID 인용까지 업무 완료했다. 보고서와 모델 체크포인트에 합성 기밀값이 없고 실제 사용자 Task를 대신 실행하지 않았음을 구분한다.

역할 행렬 100개·양성 dispatch 5개·금지 dispatch 72개·운영자 접근 거부 8개, Beta 28개·첨부 17개·이전 프리셋 호환 29개도 통과했다. 실제 OAuth 역할 루프는 44개 검사·13회·32,482토큰, 목표·첨부 자동 실행은 28개·21회·69,734토큰으로 확인했다. 기존 업무 시나리오는 완료 기록 재검사 74개이며 신규 추론으로 집계하지 않는다. 격리 계정은 갱신 토큰 없이 액세스 토큰만 사용했고 실행 중 갱신 검사는 건너뛰었다. 적용 전 현 작업 DB·Vault 백업과 격리 DB 복원 검증을 수행했으며 원래 사용자 Task의 상태·실행 수·Work Order·기밀 묶음과 첨부 해시를 보존했다.

### 첨부 기밀 처리 · 2026-10-20

Handler의 값 없는 `credential.inspect`, Agent의 Work Order 전용 `credential.import`·`credential.check`, Vault 묶음과 버전 고정 인증 커넥터를 추가했다. `.env` 역할 미리보기에서 값·주석·base64를 제외하고 Worker 입력도 차단한다. 저장 왕복과 서비스 신원 확인을 분리하며, 커넥터가 없는 경우에도 적재·보고서를 수행하고 미검증 범위를 `partial`로 반환한다. Task 최종화가 부분 완료를 전체 완료로 바꾸던 오류도 수정했다. 같은 Task의 재실행은 새 실행·Work Order를 만들며 이전 결과와 원본 파일을 보존한다. [지원 형식·권한·인증 범위](CREDENTIALS.md)를 따른다.

격리 Compose 환경에서 소유한 합성 기밀만 사용했다. Rust 29개·OIDC 1개·웹 11개, 격리 PostgreSQL 6개, 역할 행렬 100개와 양성 dispatch 5개·금지 dispatch 72개·운영자 접근 거부 8개, 기존 Beta 28개·첨부 17개 검사가 통과했다. 실제 OAuth 역할 루프는 44개 검사·13회 모델 호출·31,566토큰, 목표·첨부 자동 실행은 28개 검사·22회·70,763토큰, 목표만 입력한 강제 중단·명시적 재개는 17개 검사·15회·37,128토큰으로 통과했다. 이 격리 실행은 계정 갱신 토큰을 복사하지 않았고 `-SkipRefreshCheck`를 사용했으므로 실행 중 OAuth 갱신의 신규 증거가 아니다.

`Verify-Credentials.ps1 -Live -ResumeLive`의 최종 48개 검사가 통과했다. 승인된 합성 Jenkins 연결의 실제 LLM 실행은 18회·49,767토큰으로 Agent의 적재·신원 확인·보고서를 완료했다. 연결이 없는 Task도 실제 적재와 보고서를 만들었고, 부분 완료 표시 수정 후 같은 Task의 재실행은 15회·40,083토큰으로 `partial`을 보존했다. 이어서 ‘Vault 도구 없음’이라는 과거 Handler 계약과 이미 소진된 지시 예산을 남긴 회귀 시범은 16회·43,945토큰으로 현재 도구·예산을 다시 설정하고 Agent가 적재 도구를 실행했다. Vault 묶음은 중복 없이 하나이며 이전 Work Order·결과는 유지했다. 실패한 최초 부분 완료 표시 검증도 원래 실행으로 보존했고, 재검사에서 완료된 모델 요청은 반복하지 않았다. 각 보고서와 모델 체크포인트에 합성 비밀값이 없는지도 확인했다. 이 수치는 나열한 개별 시범의 사용량이며 전체 개발 계정 비용을 합산한 값이 아니다.

기존 완료 업무 시나리오는 `Verify-WorkScenarios.ps1 -Resume` 74개로 다시 확인했으며 새 시나리오 추론으로 집계하지 않는다. 패치 전 작업 DB·Vault 백업과 빈 격리 DB 복원·개수 비교도 통과했다. Vault 재해 복구를 수행한 것은 아니다. 실제 사용자 기밀 파일의 적재·인증 또는 원래 차단 Task의 재실행은 이 개발 검증에 포함하지 않는다.

### 파일 드래그 앤 드롭 · 2026-10-20

새 Task와 기존 Task의 Brief·Outputs에서 공통 첨부 영역으로 파일을 끌어 넣을 수 있다. 파일 선택 버튼도 유지한다. 드래그 진입·이탈 강조, 중첩 요소 이동, 전송 중 잠금, 폴더 거부와 영역 밖 파일 드롭 시 화면 이탈 방지를 처리한다. 새 Task는 기존 목록과 합쳐 파일당 1 MiB·최대 16개·합계 4 MiB·중복 이름 제한을 검사하고, 잘못된 추가는 이전 목록을 보존한다. 기존 Task는 종전처럼 한 번에 한 파일을 등록하며 실행 중 첨부 제한을 유지한다.

웹 검사 11개 중 6개는 실제 React DOM의 드래그 이벤트·파일 선택·목록 보존·첨부 취소·비활성 상태·탐색 방지의 통합 검사다. 웹 빌드와 Rust 26개·OIDC 1개 검사도 통과했다. 브라우저에서는 새 첨부 영역, 실제 파일 선택, 중복 오류 후 목록 보존과 취소를 확인했다.

작업 DB를 비워둔 상태를 유지하기 위해 DB·Vault·Worker가 분리된 임시 Compose 환경에서 `Verify-Beta.ps1` 28개, `Verify-Attachments.ps1` 17개, `Verify-GoalLaunch.ps1 -WithAttachments` 28개 검사를 수행했다. 마지막 검사는 실제 OAuth 계정으로 모델 19회·49,879토큰을 사용해 첨부 바이트·Handler 입력 권한·보고서 검증표식과 해시를 확인했다. 임시 환경은 검증 후 제거하고, 실사용 업무실의 Task·지식·파일은 생성하지 않는다.

## 실무 시범과 관찰 비용

실제 연결 계정의 `gpt-6.1-sol`을 사용했다. 보고서는 승인한 로컬 API에 인증된 GET을 수행해 120건 중 108건 해결·12건 대기·현재 90%와 과거 80%의 반증 이력을 구분하고 고정 ID/버전을 인용했다. 세 프로필 모두 실제 `report.md`와 원본 해시·API 영수증을 검사했다.

| 보고서 프로필 | 완료 응답 입력 토큰 | 출력 토큰 | 모델 호출 | 관찰 시간 |

| Handler/Agent 전체 정보 기준 | 48,891 | 2,641 | 11 | 101.848초 |
| Analyst 선별 | 29,815 | 3,345 | 14 | 123.919초 |

Analyst 선별의 입력은 기준보다 39.02% 적었고 프로토콜 프로필은 15.33% 많았다. **프로토콜 총 입력 25% 절감 목표는 달성하지 못했다.** 새 검색을 생략해도 고정 절차·참조 개정·실패 의존성과 모델 대화가 비용을 늘릴 수 있다. Master 준비를 더한 프로토콜 입력은 1회 71,191, 5회 재사용 시 회당 59,348.6, 10회 시 57,868.3이다. 이는 재사용 횟수로 준비 비용만 나눈 계산이며 반복 측정 결과가 아니다.

각 프로필은 같은 모델·목표·API 입력·완료 기준의 단일 합성 시범이다. 개발 과정의 소프트웨어·태그 개정 차이가 있으며 동시 부하·응답 변동도 통제한 벤치마크가 아니다. 최종 완료 기록은 재사용해 원본 산출물과 API 증거를 다시 검사했다. 회사 업무의 일반적인 절감률·정확도·재작업률이나 통계적 유의성을 주장하지 않는다.

추가 개발 비용도 남겼다. 이전 프로토콜 시범은 입력 43,424/출력 3,213, 재조회 권한을 모델이 오해해 차단된 시범은 입력 47,965/출력 3,200이었다. 이 차단 기록을 완료로 바꾸거나 삭제하지 않고 안내를 고친 뒤 새 Task에서 검증했다. 위 표는 이런 추가 개발 시도를 합산한 계정 전체 사용량·과금표가 아니다. 공급자가 사용량을 반환하지 않은 실패 요청은 완결 응답 집계에 포함할 수 없다.

복구 시범에서도 실패를 보존했다. 첫 시범에서 core의 연결 종료가 Worker supervisor를 취소하는 결함을 발견해 HTTP 요청과 독립된 실행으로 수정했다. 다음 시범은 실제 작업·산출물·재사용 영수증이 정상이었지만 Handler가 미검증 Info를 선택된 프로토콜과 혼동해 업무를 차단했다. 이 기록도 유지하고, 복구용 합성 자료와 완료 조건에서 등록 Info·활성 프로토콜·native 실행 검증의 의미를 명확히 구분했다.

코드 변경 시범은 `rates.py`와 검증 로그를 회수했고, 별도 Task에서 회수 소스와 변경되지 않은 운영자 원본 테스트를 다시 실행해 4개 모두 통과했다. 실제 실행·채택·Master 감사까지 완료 응답 입력 53,538/출력 5,283, 25회 호출을 관찰했다. 개발 중 진단·재개 대기 때문에 전체 경과 시간은 성능 비교에서 제외했다. 요청 분류는 `routing.csv`의 4개 ID·부서·우선순위가 공급 기준과 일치했으며 채택 포함 15회, 28,019토큰, 113.814초였다.

## 초기 선택과 남은 확장

아티팩트는 크기 제한이 있는 PostgreSQL BYTEA로 구현해 개정·영수증과 함께 트랜잭션·백업한다. 초기 전용 볼륨 제안의 파일 어댑터를 대신한 선택이며 큰 객체 저장소는 후속 범위다. 역할별 논리 실행은 core의 서버 정책을 공유하고, 실제 shell은 별도 Worker 프로세스와 비권한 자식으로 분리한다. 분산 Worker lease·재할당은 현재 단일 Worker의 직렬 처리·고정 작업 키·결과 캐시를 넘어서는 확장이다.

선택적 벡터 검색, WCM 호스트 브리지, Codex app-server, Office/PDF 전용 처리, 외부 업무 변경 커넥터와 원격 다중 사용자 로그인은 이 베타에 포함하지 않는다. 명시적 OpenAI API 키 어댑터는 구현했지만 실제 API 키 계정이 없어 그 경로의 실추론을 검증하지 않았다. 외부 변경 커넥터는 별도의 멱등·상태 조정·권한 계약을 갖춰 추가해야 한다.
