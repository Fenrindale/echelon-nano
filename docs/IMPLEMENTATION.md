# 첫 로컬 베타 구현과 검증

베타 0.2 · 2026년 10월 19일 · Windows / PowerShell 7 / Docker Desktop Linux.

`PLAN.ko.md`의 첫 사용 가능한 베타와 세 가지 실무 시범을 기준으로 한다. 아래 검증은 소유한 합성 자료를 사용했으며 실제 회사 시스템의 배포·발송·업무 변경을 뜻하지 않는다. 계정 원문, 자격증명, 체크포인트와 복원 자료는 공개하지 않는다.

## 기능 범위

| 기능 | 구현과 확인 범위 |
| --- | --- |
| 중앙 지식·Context Pack | Data/Info/Intel, 적재 방식, 태그·관계·개정·실패 보존, Task 범위의 고정 참조와 반증·의존·만료 경고 |

첫 버전의 운영자 로그인은 사용자의 요청에 따라 유보했다. 로컬 화면에 접속한 사용자는 운영자이며 자동 세션은 CSRF 처리용이다. ChatGPT 모델 OAuth 및 역할별 서명·Task·Work Order 권한은 계속 검사한다. 원격 다중 사용자 배포의 인증 체계로 사용하지 않는다.

## 재현 가능한 검사

## 실무 시범과 관찰 비용

실제 연결 계정의 `gpt-6.1-sol`을 사용했다. 보고서는 승인한 로컬 API에 인증된 GET을 수행해 120건 중 108건 해결·12건 대기·현재 90%와 과거 80%의 반증 이력을 구분하고 고정 ID/버전을 인용했다. 세 프로필 모두 실제 `report.md`와 원본 해시·API 영수증을 검사했다.

| 보고서 프로필 | 완료 응답 입력 토큰 | 출력 토큰 | 모델 호출 | 관찰 시간 |
| --- | ---: | ---: | ---: | ---: |
| Handler/Agent 전체 정보 기준 | 48,891 | 2,641 | 11 | 101.848초 |
| Analyst 선별 | 29,815 | 3,345 | 14 | 123.919초 |
| 프로토콜 직접 로드·고정 절차 | 56,388 | 3,177 | 14 | 115.923초 |
| Master 프로토콜 준비·감사 | 14,803 | 1,047 | 6 | 43.202초 |

Analyst 선별의 입력은 기준보다 39.02% 적었고 프로토콜 프로필은 15.33% 많았다. **프로토콜 총 입력 25% 절감 목표는 달성하지 못했다.** 새 검색을 생략해도 고정 절차·참조 개정·실패 의존성과 모델 대화가 비용을 늘릴 수 있다. Master 준비를 더한 프로토콜 입력은 1회 71,191, 5회 재사용 시 회당 59,348.6, 10회 시 57,868.3이다. 이는 재사용 횟수로 준비 비용만 나눈 계산이며 반복 측정 결과가 아니다.

각 프로필은 같은 모델·목표·API 입력·완료 기준의 단일 합성 시범이다. 개발 과정의 소프트웨어·태그 개정 차이가 있으며 동시 부하·응답 변동도 통제한 벤치마크가 아니다. 최종 완료 기록은 재사용해 원본 산출물과 API 증거를 다시 검사했다. 회사 업무의 일반적인 절감률·정확도·재작업률이나 통계적 유의성을 주장하지 않는다.

추가 개발 비용도 남겼다. 이전 프로토콜 시범은 입력 43,424/출력 3,213, 재조회 권한을 모델이 오해해 차단된 시범은 입력 47,965/출력 3,200이었다. 이 차단 기록을 완료로 바꾸거나 삭제하지 않고 안내를 고친 뒤 새 Task에서 검증했다. 위 표는 이런 추가 개발 시도를 합산한 계정 전체 사용량·과금표가 아니다. 공급자가 사용량을 반환하지 않은 실패 요청은 완결 응답 집계에 포함할 수 없다.

복구 시범에서도 실패를 보존했다. 첫 시범에서 core의 연결 종료가 Worker supervisor를 취소하는 결함을 발견해 HTTP 요청과 독립된 실행으로 수정했다. 다음 시범은 실제 작업·산출물·재사용 영수증이 정상이었지만 Handler가 미검증 Info를 선택된 프로토콜과 혼동해 업무를 차단했다. 이 기록도 유지하고, 복구용 합성 자료와 완료 조건에서 등록 Info·활성 프로토콜·native 실행 검증의 의미를 명확히 구분했다.

코드 변경 시범은 `rates.py`와 검증 로그를 회수했고, 별도 Task에서 회수 소스와 변경되지 않은 운영자 원본 테스트를 다시 실행해 4개 모두 통과했다. 실제 실행·채택·Master 감사까지 완료 응답 입력 53,538/출력 5,283, 25회 호출을 관찰했다. 개발 중 진단·재개 대기 때문에 전체 경과 시간은 성능 비교에서 제외했다. 요청 분류는 `routing.csv`의 4개 ID·부서·우선순위가 공급 기준과 일치했으며 채택 포함 15회, 28,019토큰, 113.814초였다.

## 초기 선택과 남은 확장

아티팩트는 크기 제한이 있는 PostgreSQL BYTEA로 구현해 개정·영수증과 함께 트랜잭션·백업한다. 초기 전용 볼륨 제안의 파일 어댑터를 대신한 선택이며 큰 객체 저장소는 후속 범위다. 역할별 논리 실행은 core의 서버 정책을 공유하고, 실제 shell은 별도 Worker 프로세스와 비권한 자식으로 분리한다. 분산 Worker lease·재할당은 현재 단일 Worker의 직렬 처리·고정 작업 키·결과 캐시를 넘어서는 확장이다.

선택적 벡터 검색, WCM 호스트 브리지, Codex app-server, Office/PDF 전용 처리, 외부 업무 변경 커넥터와 원격 다중 사용자 로그인은 이 베타에 포함하지 않는다. 명시적 OpenAI API 키 어댑터는 구현했지만 실제 API 키 계정이 없어 그 경로의 실추론을 검증하지 않았다. 외부 변경 커넥터는 별도의 멱등·상태 조정·권한 계약을 갖춰 추가해야 한다.
